# CoursePlan 产品规格（MVP）

## 产品定位

CoursePlan 是一个由用户自己的 Agent 驱动的选课工作流。前端完全可选，仅用于呈现培养进度、完整课程池和课表方案。

核心闭环：导入个人资料 → 计算完整课程池 → 与 Agent 确认偏好 → 生成并比较日历课表方案。

## 阶段

### 0. 个人数据初始化

- 培养计划：专业、入学年份、学院、Major/Minor、必修与选修要求、学分、替代与互斥规则。
- 修课记录：已修、在修、成绩/通过状态、transfer credit、exemption、退课或未通过记录。
- 输出 Eligibility Snapshot，所有判断必须包含原因和可信状态。

### 1. 候选课程计算

1. 剔除已完成课程。
2. 剔除本学期未开设课程。
3. 检查先修、并修、重复修读和互斥规则。
4. 处理替代课程和培养要求适用性。
5. 检查专业、学院、年级限制。
6. 对 consent、预留名额等无法确定的条件明确标记。

高年级课程默认标记而非删除。课程资格状态包括：推荐、可选、可能可选、不推荐、暂不可选、需要人工确认。

### 2. 人工缩减候选集合

主界面使用极简表格。用户可以全选、取消、反选、批量排除和恢复课程。排除是可撤销的状态变更，不删除底层数据，并记录操作者与原因。

### 3. 时间轴淘汰

先展示课程可能出现的时间范围，再按需展开具体 Enrollment Option。冲突直接叠加在时间轴上，用户可从时间块右上角排除组合。

数据层级固定为 Course → Enrollment Option → Meeting。一门课可能由 Lecture、Tutorial、Lab 的绑定组合构成。

### 4. 手动排课与 Agent 排课

用户可以直接选择组合，也可以要求 Agent 按上课天数、早晚课、午饭、连续上课、教学地点、培养要求、余位和 consent 等条件生成多个可解释方案。

## 学生上下文

仓库不保存真实学生档案。运行时由用户提供入学年份、专业、方向、书院、年级、目标学期、已修课程、豁免或转学分、学分上限和时间偏好。系统不得在缺少专业和资格依据时生成确定性推荐。

## 当前 MVP 范围

- 新增阶段 0「培养计划 Status」，完整呈现必要要求、所属模块和完成状态。
- 实现阶段导航、真实个人摘要和未完成要求表格。
- 支持表格选择、批量排除、恢复、隐藏高年级课程和要求筛选。
- 候选课程不再使用虚构示例；在正式数据复核前仅呈现未完成要求并标记“待核验”。
- 时间表和 Agent 方案生成保留入口，下一阶段实现。
