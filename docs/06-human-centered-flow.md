# 人性化选课流程（待实施）

## 原则

- 页面表达用户任务，不暴露“匹配数据库”等系统内部步骤。
- 主按钮必须始终对应当前可执行的动作，不能把用户带入死路。
- 后台计算通过进度和结果状态呈现，不单独占用一个空页面。
- 不确定课程继续保留并解释原因，只有明确不可选的课程才默认隐藏。

## 首次使用

确认培养计划 → 确认修课记录 → 系统自动构建课程池 → 开始本学期规划。

若数据缺失，主按钮必须直接指向解决动作，例如“导入修课记录”；若系统正在处理，应显示具体进度，完成后自动进入课程池。

## 日常主流程

1. 本学期可选课程池
2. 时间分布
3. 方案比较与保存

培养计划和修课记录作为独立资料页存在，不在每次选课时阻挡用户。

## 可选课程池

完整课程池由以下部分构成：明确未完成要求、专业与商学院选修、通识与书院课程、自由选修。页面必须展示课程进入课程池的原因、可计入的要求、资格状态和开课信息。

## 时间分布

先展示课程可能时间范围，再展开具体 Enrollment Option。冲突直接叠加在时间轴上；TBA 课程必须独立呈现，不能静默消失。

## 排课方案

用户可以手动选择，也可以由 Agent 按集中上课、避免早晚课、保留午饭、减少通勤、培养要求优先、余位和 consent 等偏好生成多个可解释方案。
