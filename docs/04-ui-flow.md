# 页面结构与交互流程

## Minimal 第一屏：培养计划 Status

1. 顶栏：产品名、学期切换、低干扰 Agent 入口、个人入口。
2. Hero：未初始化时显示通用引导；初始化后显示当前学生主动提供的培养背景和完成统计。
3. 四阶段导航：培养计划、候选课程、时间排布、生成方案。
4. Status 表格：课程/必要要求、所属模块、规则说明、完成状态。
5. 支持按模块和完成状态筛选；核对后进入候选课程阶段。

可选课程池不等于未完成培养要求。课程池必须同时覆盖：明确未完成要求、专业与商学院选修、通识与书院课程、自由选修。未完成要求只作为优先匹配输入；在官方开课和个人资格核验完成前，不能显示虚假的候选课总数。

## 表格行为

- 默认选中规则引擎保留的课程。
- 全选、取消和反选只作用于当前可见集合。
- 排除所选将课程移入 excludedCourses，不删除记录。
- 高年级课程通过筛选器隐藏，不默认永久排除。
- 点击课程代码后续打开解释抽屉，展示资格理由、培养要求和不确定项。

## 时间排布页（下一阶段）

- 默认使用候选时间范围的半透明密度视图。
- 点击课程展开 Enrollment Option。
- 课程块右上角可排除对应组合。
- 冲突区直接使用红色叠加显示，不设置独立“体检”侧栏。
- TBA meeting 独立列出，不能从课表中静默消失。
