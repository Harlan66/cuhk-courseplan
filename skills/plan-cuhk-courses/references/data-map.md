# Project data map

Use paths relative to the repository root.

## Personal state

- `data/student/profile.json`: identity, programme, target term, unit ceiling, constraints, preferences.
- `data/student/course-history.json`: completed, in-progress, exempted, and transferred courses.
- `data/student/schedule-plans.json`: agent-generated alternatives rendered by the frontend.

## Graduation and eligibility

- `data/curriculum/requirements.json`: personal requirement completion and choice pools.
- `data/curriculum/course-prerequisites.json`: verified prerequisite expressions and unknown-rule flags.
- `data/curriculum/eligibility-rules.json`: versioned requirement, exclusion, substitution, consent, and uncertainty policy.
- `data/curriculum/catalog-verification-queue.json`: rules still requiring CUSIS or department confirmation.
- `data/cuhk/2024/clean/`: audited programme evidence for all collected programmes.

## Term data

Resolve the newest curated directory matching the student's target term under `data/cuhk-timetable/curated/`; never hard-code a snapshot date or term.

- `courses.csv`: course metadata.
- `classes.csv`: class number, component, vacancy, consent, units.
- `meetings.csv`: day, time, room, date range by class number.
- `reserved_quotas.csv`: known quota restrictions.
- `subjects.csv`: subject capture and school-approval status.
- `quality_report.json`: coverage and integrity counts.

## Generated frontend data

- `app/generated-course-pool.json`: local course pool generated by `scripts/build_personal_course_pool.mjs`; the script reads the target term and programme subjects from runtime data.
- `app/course-planner.tsx`: frontend renderer; do not hard-code a new shortlist here.

When the term changes, resolve the matching curated snapshot instead of silently reusing Term 1 data.
